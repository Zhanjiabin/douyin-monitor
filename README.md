# 观潮 · 抖音内容情报与增长分析平台

MediaCrawlerPro（除 Go 版）、TikHub 与原有 DouK 已接入统一工作空间。双击 `启动.bat` 或运行 `python scripts/start_stack.py`，默认打开账号卡片工作台 `/home`。各项目作用、安装、数据来源与配置说明见 [统一接入文档](docs/unified-integrations.md)。主要入口：`/home` 工作台、`/screen` 监控、`/research` 内容研究、`/collect` 采集中心、`/assets` 素材、`/settings` 设置。新采集中心默认使用已验证的 TikHub 接口，原采集器和独立工作室收纳到高级工具；历史数据保留。[全接口工作台](docs/tikhub-api.md)仍覆盖 1,058 个接口。服务器迁移条件见[部署评估](docs/server-deployment.md)。 播放统计默认单作品接口；作品勾选刷新及账号、范围、期限、频率设置见[定时监控](docs/monitoring.md)。

基于 [zouzibo-tech/douyin-playcount-monitor](https://github.com/zouzibo-tech/douyin-playcount-monitor) 的采集内核进行扩展。保留 Playwright 浏览器响应监听、SQLite 历史快照、增量计算、定时任务、Excel 导出和本地运行模式。

## 当前版本

「发现」入口 `/discover` 包含作品发现、热点趋势和关键词追踪。默认使用 TikHub：作品为「AI 原生影像」分类的低粉爆款榜，热点为上升热点；提供高完播/点赞/涨粉率榜、关键词作品、话题/搜索飙升和行业趋势。搜索与重置仅读取缓存，抓取前确认请求数，默认一页。MediaCrawlerPro 搜索和原生下载保留为手动工具。工作台账号详情可查询公开粉丝画像，内容研究提供同账号、同发布年龄、同来源和采集日的样本比较，不将相关性解释为推流原因。用法、价格核对与接口边界见[发现与趋势说明](docs/discovery-development.md)。

搜索只读取缓存，抓取最新先预览请求数再确认；榜单默认抓一页，后续页须主动点击。关键词热度专用接口默认关闭，每次一个词，许可与批量视频统计分开。发现定时计划默认不启用，启用后共享已有请求限额；失败不自动重试。流量来源、留存、跳出等创作者后台私有指标不在本次产品范围内，不需要提供创作者 Cookie。

工作台默认按监控账号展示最新发布的三条作品；点击账号卡片打开完整入库作品明细，点击作品查看文案、互动、评论、素材与历史。账号详情和内容库保留已入库的旧作品，不因 90 天内未采集而消失。全部日常页面的筛选和搜索位于顶部横向工具栏，修改条件须点击「搜索」才应用；重置后立即恢复默认条件并重新搜索缓存，刷新页面数据保留未提交条件。账号和题材不再触发隐式过滤。评论采集、作品下载和播放刷新在当前页面预览并确认；素材列表可直接下载本地文件。


新增 **采集工作台 `/studio`**：完整收录 TikTokDownloader / DouK-Downloader 5.8 源码，固定版本并在独立 Python 环境运行；将其 26 个可用采集入口接到本项目的任务队列、下载文件、设置与作品监控。使用说明、功能覆盖与验证范围见 [集成文档](docs/douk-integration.md)。

`/screen` 作品监控支持账号分组、顶部条件搜索、7/30/90 天观测窗口、作品历史、CSV 导出和全屏展示。「题材研究」与「标题分析」已从日常界面移除，旧页面书签会返回作品监控。所有指标来自真实本地快照。

添加账号、备注、分组和启停监控已并入工作台，侧栏不再提供独立的「监控账号」页面。账号弹窗采用紧凑表格和独立列表滚动；总条数、每页条数与指定页码跳转统一放在底部分页栏。工作台、作品监控、内容列表、采集任务、任务结果、素材库和旧采集结果共用分页组件。

账号弹窗的每条作品均可点击「更新数据」，默认使用单作品统计接口；预览并确认后只刷新所选作品，结果直接更新到弹窗中。设置页分为「定时监控」「接口连接」「高级工具」，保留账号范围、频率、期限、请求限额和批量许可；未保存修改不会因切换标签页丢失。

新增数据库测试覆盖账号分组、日期间隔、来源切换、缺失/过期值、每日补采以及仅账号监控的补跑。执行：`python -m unittest discover -s tests -v`。

2026-11-04 本地验证发现部分合集页面改走 `series/aweme`，响应中的 `play_count` 为 0 占位值。采集器会明确提示该接口口径尚未验证，不把它作为真实零播放保存。账号作品发现仍可记录标题、发布时间和公开互动；是否取得合集播放量取决于目标页面实际暴露的接口。

本分支第一阶段以**真实数据接入 + 信息架构重构**为目标：

- 数据总览：真实合集总播放、日增、监控数量、停涨与数据健康状态。
- 账号矩阵：从已采集合集归并作者维度，显示账号作品覆盖及表现。
- 视频监控：展示已采集合集内分集的播放、点赞、评论、收藏及历史增量。
- 合集监控：按合集维度展示官方总播放、分集求和校验、集数与更新状态。
- 赛道情报：对已采集作品标题做轻量关键词归纳；样本不足时明确提示。
- AI 起号工作台：根据本地真实采集样本生成可解释的规则型诊断草案。当前不调用外部 LLM，不将规则建议冒充模型生成。
- 预警中心：采集失败、数据校验差异、停涨与新采集状态。

## 数据边界

原合集采集器主要覆盖发布在抖音合集中的视频；日常账号发现与作品统计已接入 TikHub。平台未返回的曝光、完播率和推荐流量来源不会伪造或估算成实测数据。高完播率榜表示榜单入选，不能查询任意同行作品的后台完播率；榜单播放、累计播放、热度指数分列展示。账号与作品发现按明确页数执行，实际返回数量不等于平台主页声称的作品总数。

## 运行

沿用上游要求：Windows 10/11、系统 Edge；源码运行：

```bash
pip install -r requirements.txt
# 默认使用系统 Edge，无需另装 Chromium
python src/app.py
```

程序只监听 `127.0.0.1`。请遵守抖音平台条款并控制采集频率。

## 内容情报扩展

- **数据总览 / 账号矩阵 / 视频监控 / 合集监控**：基于 SQLite 的真实合集与分集快照，不造数。
- **自定义监控合集**：使用关键词把当前已采集的视频标题和合集名称归类；这不是全站自动搜索，未进入监控清单的作品不会自动出现。
- **赛道情报**：只分析本地已采集标题样本，不代表全站趋势。
- **预警中心**：展示合集总量与分集求和差异、停涨观察和采集失败。
- **AI 起号助手**：默认提供规则诊断。可选配置 OpenAI 兼容接口后，基于本地采集的标题及播放/互动快照生成模型总结。

### 可选 AI 模型配置（Windows PowerShell）

```powershell
$env:OPENAI_API_KEY="你的 API Key"
$env:OPENAI_MODEL="gpt-4o-mini"
$env:OPENAI_BASE_URL="https://api.openai.com/v1"
python src/app.py
```

只有配置 API Key 并点击 AI 分析时，最多 30 条已采集视频的标题和公开播放/互动计数会发送到所配置的模型服务。未配置时不发送任何数据。不要把 API Key 写进仓库或提交到 Git。

**边界**：上游采集器通过视频链接解析合集。账号矩阵目前按已识别作者归并，并非账号全部作品的自动发现；不在合集中的视频播放量、曝光、完播率、推荐流量来源等平台未公开指标不会被推算。

## 账号自动发现与独立视频监控

1. 打开「账号矩阵」，粘贴抖音账号主页地址（形如 `https://www.douyin.com/user/SEC_UID`），加入监控。
2. 点击「立即采集」或等待已配置的定时任务。程序会打开账号公开主页，监听作品列表响应，按配置滚动发现最近作品。
3. 发现的作品按 aweme_id 独立保存标题、发布时间、所属合集、首次发现/最近发现时间及每日可取得的互动快照。
4. 对发现作品所属的合集，程序使用合集分集接口补采播放量；已知合集每天刷新，当天发现新作品也会补采。优先处理最久未采的合集，并按每账号每轮上限控制请求量。未取全的合集保留待补采状态。
5. 视频监控中可点标题查看该视频的历史快照；非合集作品若平台未公开真实播放量，界面显示「平台未公开」，仍可记录公开的点赞、评论、分享、收藏等字段（字段是否返回取决于平台响应）。

默认发现设置：每个账号扫描最近 4 页作品；每轮最多补采 5 个待刷新合集。可在 `config.json` 调整 `account_discovery_pages` 与 `account_discovery_mix_limit`。扫描页数以外的旧合集仍需通过视频清单显式监控。

**重要数据口径**：上游实测中，作者作品列表接口的 `statistics.play_count` 对他人作品可能返回 0 占位值。因此非合集视频的 0 不会被保存为真实播放量；除非接口确实返回正数，否则记录为「未公开」。曝光、完播率、推荐流量来源等不可见指标不推算。账号发现范围受抖音公开页面分页、访问状态和页面接口变化影响，并非账号全部历史作品的保证性归档。


### 主页完整性与紧凑作品表

`/screen` 的作品表按发布时间排序，可查看封面、合集、账号、发布时间、播放、点赞、评论、收藏、分享，支持搜索、排序和 25/50/100 条分页。没有两日可比快照时不展示空趋势图。账号页分别展示主页已采数、主页声明总数与合集补充作品数。

采集会定位作品列表滚动容器，等待新作品、去重、有限重试；分页默认最多 30 页（配置 `account_discovery_pages`，最多 100）。遇到登录限制、翻页停滞、页数上限或用户停止，会保留已取作品并显示未完成原因。主页总数与公开接口返回条数可能不同，列表返回结束不代表所有声明作品均可见。

点击 **登录采集浏览器**，在抖音官方窗口登录后关闭窗口，再点 **立即采集**。这使用本项目的 `.browser_profile`，不会读取其他浏览器的登录凭据。窗口开启期间暂停其他采集，最长等待 10 分钟，也可用停止按钮结束。登录可以解决页面明确提示的历史作品加载限制，但不保证平台提供单集播放量；未验证的播放量仍记为缺失。

头像和公开作品封面缓存到 `data/media/`，通过本机 `/media/` 读取。下载失败不会阻止作品入库。作品采集异常与合集播放补采提示分开记录；已确认不提供验证播放量的合集当天不重复补采，次日或新作品时重新尝试。


作品标题和账号名称直接跳转抖音，数据详情与账号筛选使用单独入口。播放量缺失分别显示“主页未提供”“合集待补采”“接口未提供”“补采失败”，具体证据在详情查看。

视频详情页的合集接口可能只返回当前集附近的分段，即使 `has_more=0`，也不能说明整个合集采完。账号采集现在用已发现但未覆盖的作品依次打开详情页，合并、去重各段，并与合集声明集数及已知作品对账；中途失败保留已取分段。`scripts/refresh_playback.py` 可使用已有主页作品单独补采合集播放，不必重扫主页。该方式仍不能取得接口没有提供有效值的指标。


### 2026-11-04：主动请求合集播放接口

实测发现：页面可能只自动调用 `series/aweme`（播放字段为零占位），但在同一浏览器里主动请求 `/aweme/v1/web/mix/aweme/` 仍会返回有效播放量。采集器现优先在页面内请求这个已知接口，从 cursor=0 开始按响应 cursor/has_more 翻页；失败时才回退到页面响应与分段导航。请求有超时、页数上限、重复页检测及合集/作者匹配检查，不导出 Cookie，也不逆向签名。

因此，过去“页面没有返回 mix/aweme 就表示接口没有播放量”的判断已修正。对照证据保存在本机 `output/playback-route-audit.json`。当前未标注合集的作品显示“待查播放来源”，不意味着其它路径一定不可获得。
