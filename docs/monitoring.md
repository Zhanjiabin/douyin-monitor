# 单作品刷新与定时监控

## 播放统计开关

默认仅使用 `fetch_video_statistics`，每次只传一个作品 ID。选择 N 条作品会预览 N 次请求，不自动改用 `fetch_multi_video_statistics`。

在 `/settings` 的“接口连接”标签页中明确勾选“允许批量播放统计”并保存后，采集中心、选中刷新和定时计划才允许选择批量方式；即使开启许可，默认方式仍是单作品。该开关在后端执行，旧播放补采、全部 API 工作台、排队任务均受约束；关闭后中途任务不会继续发出下一次批量请求。已完成的历史批量数据保留来源，不删除。

## 手动刷新

账号新增、分组、备注与暂停监控在工作台的「添加账号」或卡片「管理」中操作，修改后点击保存。工作台的账号详情弹窗可在作品行直接点击“更新数据”，预览并确认后按单作品接口获取最新播放及返回的互动数据；完成后原地更新。监控页 `/screen` 也可勾选单条或本页作品，点击“刷新选中数据”。对话框列出选中作品、统计方式、请求数及限额；“确认刷新”才会创建任务，结束后更新表格。请求上限与每日限额仍由数据连接设置控制。超过限额会拒绝整次提交，不悄悄缩小范围或切换接口。

产品接口：

- `POST /api/workbench/refresh-plan`：离线预览，传入字符串数组 `video_ids`，可选 `playback_method`（默认 `single`）。
- `POST /api/workbench/refresh`：传入相同选择、预览的 `fingerprint` 及 `confirmed: true`，返回队列任务 ID。
- `GET /api/douk/jobs/{id}`：读取结果与回写记录。

## 定时计划

`/settings#monitoringSettings` 提供：账号多选、最近几天发布的作品、每天定点 / 分钟间隔、开始日期、可选结束日期和独立的批量使用选项。时间统一为北京时间 `Asia/Shanghai`，结束日期包含当天；空结束日期表示持续监控。

初始预设是每天 09:00、近 7 天、单作品接口，**定时开关默认关闭**。选择账号并启用、保存计划，才授权按该配置使用接口额度。保存不会立即调用供应商，从下一时间点开始。预览会显示当前范围的作品和请求数；若超过每任务 / 每日限额，启用保存会提示先调整范围或连接限额。

刷新对象是已入库且仍启用账号的作品，以作品 `create_time` 筛选，缺失发布时间和未来时间不会混入。发现新发布作品可在账号详情弹窗点击「同步最新作品」，也可在采集中心同步账号；此计划不会额外调用账号列表或详情接口。手动指定作品刷新可超出这个自动监控范围。

默认每任务上限为 5 次。如果当前近一周范围超过 5 条，应自行缩小账号范围或在数据连接中提高该限额；不会通过拆成多个任务绕过限额。后续范围变大、Key 被清除或额度耗尽时，该轮记录为阻止，不自动改用批量或只刷新一部分。

运行条件：程序 / 服务器保持运行。睡眠或关闭期间无法执行；重启只补当前最近一轮，不补发所有错过的频次。修改计划后重新计算下次时间。上一轮未结束时下一轮跳过。停用、到期或修改范围会阻止已排队计划继续发出后续请求，已在途的一次请求可能仍然返回和计费。

## 持久化与验证

`monitor_policy` 保存公开计划与版本；`monitor_schedule_runs` 为每个版本和时间槽持久化一次唯一提交。先记录时间槽再入队；失败、进程退出或重新启动不会重发同一个槽。提交中断会标记为中断并保留记录。任务仍复用正常队列、`playback_requests` 账本及 `tikhub_app` 来源的有效播放回写。

- `GET /api/monitoring/status`：计划、下次执行、当前范围、限额与执行记录，不返回 Key。
- `POST /api/monitoring/preview`：校验并预览配置，不发付费请求。
- `POST /api/monitoring/settings`：保存计划；`enabled: true` 表示启用其定时授权。

测试：`tests/test_monitoring.py`、`scripts/check_monitoring_ui.py`。测试使用临时数据库和模拟传输，覆盖全入口批量禁用、单 ID 请求、北京时间、范围与频率、暂停/到期、共享限额、重启去重、排队任务停用和手动回写。
