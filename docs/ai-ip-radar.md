# AI 内容发现与 IP 雷达

入口：`/discover`。AI 作品、IP 雷达、内容报告都只读本地保存的数据；筛选、翻页和报告生成不调用 TikHub。

## 自动流程

1. 轮换搜索 AI 漫剧、真人短剧、萌宠和电影等方向词。默认每轮一个词，搜索近七天作品。
2. 从合集名、书名号剧名、分集前缀及同作者反复出现的特色标签建立候选。作者 ID 未核实时明确标为待核实。解说、二创和合集单独分组，不能据此断定版权归属或已经观看成片。
3. 从近期作品中按方向轮换选取重点样本，限制同一作者占用的名额。默认最多 12 条，近 14 天发布。
4. 用 `fetch_one_video_v3` 核实作者、剧集和互动字段，用 **`fetch_video_statistics` 单作品请求**获取播放。不存在批量统计后备路径。三天内有效详情可复用，单作品统计按设置的间隔刷新。
5. 每次响应写入任务回执、请求台账及追加式指标历史。没有返回的字段保留空值；已有有效值不会因漏返而消失。榜单窗口播放不充当作品播放。
6. 日报、周报按报告截止时间读取当时的证据，包含新候选、近期参考、真实增长和搜索记录。不会把后来的补采写进旧报告。

默认计划关闭，由网站保存计划或部署初始化显式开启：每 6 小时巡检，每轮最多 5 次、AI 雷达每天最多 30 次，同时服从全站每日调用上限。后台每 15 秒检查是否到期，槽位只提交一次。修改或关闭计划会阻止待执行的后续请求。失败和空响应同样进入冷却期，不进行付费自动重试。

扩词只接受至少两条作品支持的特色剧名，最多增加 12 个。每三次方向搜索后才轮到一次扩展词，防止已知 IP 占满搜索；原始方向搜索持续保留。

## 增长与识别的限制

- 同一作品、同一来源、同一播放范围、至少间隔一小时才计算增长；优先取接近一天的比较点，超过七天不比较。
- 播放下降标记为数据修正，不制造负增长热点；48 小时以前的观测不标成当前增长。
- 初次见到的旧作品放入旧作参考，近期候选以发布时间判断。一次采集不会产生涨幅。
- 同作者基线只使用已核实身份和大致相同发布年龄的其他作品，至少三个样本才给出中位数与倍数。
- 这是公开样本中的线索发现，不是全站热度榜、语音转录或视频语义分析，也不判断平台具体推流机制。

## 调试与验收

后端：`python -m unittest discover -s tests -q`。
浏览器：`python scripts/check_ip_radar_ui.py`（真实网站和任务队列，付费传输全部模拟，覆盖筛选、重置、排序、分页、进度、历史、分组、计划、报告及桌面手机主题布局）。
配置和新表在 SQLite 中，随现有备份服务保存。TikHub 密钥继续只从服务器私有配置读取，不进入前端或 Git。
