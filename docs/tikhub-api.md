# TikHub 接口工作台

播放统计默认单作品接口，每次仅传一个 ID。批量统计默认关闭，必须先在设置明确开启；完整规则见[刷新与定时监控](monitoring.md)。

启动项目后访问 `http://127.0.0.1:8795/tikhub`，默认打开抖音 App V3 的视频播放统计。

## 覆盖范围

从 [TikHub 官方 OpenAPI](https://api.tikhub.io/openapi.json) 固定的 V5.3.2 规范生成：1,058 个接口、51 个分组，其中抖音 App V3 为 38 个。全部 GET / POST 接口经同一客户端接入，并按各自规范生成查询参数和 JSON 请求体表单。支持引用模型、顶层数组、可空字段、枚举及 64 位整数 ID；JSON 请求体和批量任务以原始文本传到 Python 解析，避免浏览器损失 ID 精度。

可筛选分组、搜索接口、收藏、从监控库带入作品与账号，查看数据表和完整响应，导出 JSON / CSV / Excel。结果保存在统一任务队列中，可查看成功、失败、部分完成和取消记录。

## 配置与请求

在右上角“连接设置”填写 API Key，与原来的 `/workspace#playback` 共用。Key 只存本机且不回显。平台需要 Cookie 的字段须单独手动填写；不会自动将本机抖音或其他平台登录交给 TikHub。

“预览请求数”只做本地校验，不发送供应商请求。执行前确认请求上限；请求数以 API 调用计，并非作品数，价格以所选官方接口为准。批量 JSON 每项一次请求；接口自身的数组请求体仍算一次调用。JSON 编辑器接受以下批量任务：

```json
[
  {"params": {"aweme_ids": "7703151458754472787"}},
  {"params": {"aweme_ids": "7703151458754472788"}}
]
```

分页计入预览上限，仅在响应明确返回 `has_more` 和新的游标时继续；未知或重复游标停止。接口未声明游标或使用 POST 时不自动翻页，可用批量任务分别指定参数 / 请求体。不同平台的非标准翻页字段可人工填入下一页值。

所有调用与旧播放补采共用 `playback_requests` 限额账本。请求发出前记录一次尝试，HTTP 或业务错误、网络失败均停止后续请求，不自动重试。失败可能已经计费；重新执行须重新预览。取消会停止剩余请求，正在传输的一次请求仍会保存响应。返回的下载重定向只展示地址，不携带 Key 自动跟随。

## 本机数据回写

支持的接口旁显示“写入”选项，取消勾选则只保存 API 结果：

- 抖音视频统计、批量统计、星图播放：沿用原来的作品 ID 校验、来源与口径存储。只有已监控作品写入历史；0 或缺失不覆盖已有有效播放，不跨来源计算增长。
- App V3 视频详情、批量详情、账号作品、合集 / 短剧 / 音乐 / 话题作品：写入监控与内容库，保留发布时间、文案、互动指标，沿用封面 / 头像本机缓存。
- App V3 视频评论和回复：写入 `dy` 评论库，验证作品 ID，按评论 ID 去重。

其余接口全部可请求、查看和导出完整结果，尚未自动映射到监控作品库。视频详情中的发布描述不是语音转录；该 API 接入不会自行生成视频逐字稿或推断抖音内部推流规则。

## 更新与验证

`integrations/tikhub.openapi.json` 保存规范，`integrations/tikhub.lock.json` 记录来源、获取时间、版本、SHA-256 及接口数量。更新：

```powershell
.venv\Scripts\python.exe scripts/sync_tikhub.py
```

更新后重启本机服务。同步只下载官方规范，不使用 API Key；新增非 GET / POST 方法、非本地 schema 引用或非法路径会拒绝同步，需要先更新客户端。

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe scripts/check_tikhub.py
```

单元测试使用临时数据库与模拟传输，覆盖完整清单与 schema、GET / POST、数组 / 对象请求体、分页、批量、取消、共享限额、隐私、回写和导出。浏览器检查逐项预览全部 38 个 App V3 表单，验证模拟统计回写、导出、收藏、搜索和桌面 / 手机布局。没有付费 Key 时不能声称所有接口或某条视频的播放量已实际取回。
